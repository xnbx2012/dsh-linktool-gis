本 Skill 是唯一的业务结果验收入口。字段非空率规则仅在此处定义，其他 Skill 不重复。

# 验收流程

## 1. 检查输出生成

- 列出输出数据库内容，确认目标数据已生成
- 未生成 → 调用 `/tool-retry`

**数据集规模快速判断**：
- 调用 `get_data_properties` 获取 `feature_count`
- 若 feature_count > 1000 且本次操作是数据转换类（Select/Clip/Project/Merge等），标记为"大数据转换"，后续跳过非空率门控
- 若 feature_count ≤ 1000，执行完整非空率检查

## 2. 验证基础属性

用 `get_data_properties` 检查：
- 投影坐标系是否正确
- 数据范围是否合理
- 要素数/记录数是否符合预期

不符合 → 调用 `/tool-retry`

## 3. 验证字段命名

合同声明了 `output_field_names` 时：
- 所有必需字段是否以精确名称存在
- 字段数据类型是否匹配
- 任一必需字段缺失或命名不符 → 调用 `/tool-retry`

## 4. 字段非空率门控（优化版）

**大数据集抽样策略**：若 `feature_count > 1000`，使用抽样而非全量遍历。

1. **确定数据集规模**：先用 `get_data_properties` 获取 `feature_count`
2. **大数据集（> 1000）抽样路径**：
   - 用 `query_feature_attributes(max_records=100)` 抽样
   - 基于抽样估算非空率，**禁止全量遍历**
   - 若抽样发现字段全为空，才扩大采样
3. **小数据集（≤ 1000）**：按原逻辑逐字段检查
4. **Shapefile SQL 限制**：禁止使用 `TRIM()`、`<>`、`IS NOT NULL` 等不支持的 SQL
   - 改用 `max_records=100` 抽样方式验证非空
5. **非评价类步骤豁免**：筛选（Select）、裁剪（Clip）、投影（Project）等数据转换步骤
   - 跳过字段非空率门控，仅验证基础属性（坐标系、要素数、范围）
   - 仅当 `validation_criteria` 明确要求字段完整性时才执行非空率检查

## 5. 抽样验证

- 用 `query_feature_attributes` 获取 ≤ 10 条示例数据
- 确认属性值符合预期

## 6. 验收标准对照

对照合同 `validation_criteria`（或用户明示目标），逐条核验：

| 维度 | 核验要点 |
|------|---------|
| 格式 | 数据类型、存储格式、必需字段、坐标系 |
| 内容 | 结果是否对应分析对象和子任务目标 |
| 数值 | 异常小数、零值率、负值/越界、数量级是否合理 |

任一项不符合 → 调用 `/tool-retry`，携带具体不符合的维度与证据。

## 4. 字段非零率门控（评价类新增）

> 本节是"验证下沉到子智能体"的核心实现：发现零值问题**当场自愈**，不得留到 Workflow 末端。

对**评价类结果**（如 PJDYT、ZHZS、ZLDJ 等）**必须执行非零率检查**：

1. **确定关键指标字段**（按任务类型确定，如 PJDYT 的 SJD/YJZ/YXL/SXJ/GCHD/TRRZ）
2. **计算零值率** = 零值记录数 / 总记录数
3. **门控阈值**：零值率 **> 80%** → `FAIL`，立即触发 `/tool-retry`
4. **零值率 ≤ 80%** → 继续验收流程

示例（耕地质量评价）：
```
关键字段: SJD, YJZ, YXL, SXJ, GCHD, TRRZ
若任意字段零值率 > 80% → FAIL
建议重试方向：检查字段计算逻辑、输入数据是否为空
```

## 5. 目标字段值分布合理性检查（评价类新增）

> 评价类结果还应检查目标字段值分布是否符合预期，防止"全为 0"以外的"全为同一值"等异常。

检查项：
- **ZLDJ（等级字段）**：等级应跨 ≥3 个不同等级；全为同一等级 → `FAIL`
- **ZHZS（综合指数）**：数值分布应有一定离散度；标准差 ≈ 0 → `FAIL`
- **因子字段**：非零值应有一定多样性；唯一值 ≤ 2 个（除 0 外）→ `FAIL`

不符合上述条件 → 调用 `/tool-retry`，携带具体问题维度与证据。

## 7. 视觉核验（按需）

面状覆盖类、叠加/裁剪/融合类结果 → 调用 `/visual-check`。

- `/visual-check` 自带门控，非适用场景自动 SKIP
- 返回 FAIL → 按其指出的问题调用 `/tool-retry`
- 返回 PASS / SKIP → 继续

## 8. 返回结果

全部验收通过后，向上游返回：
- 工具执行结果摘要
- 字段完整性报告（每个新字段的非空率和示例值）
- 验收标准对照结论（逐条 ✅/❌）
- 视觉核验结论（PASS/SKIP）
- 3 行输出数据示例
## plan0701 Workflow 返回要求

- 核查结果必须以结构化形式返回给上游 Workflow，包含 `status`、`errors`、`warnings`、`validation`。
- 发现失败点时尽早返回结构化失败，供 Workflow 收集到 `errors[]`，不得用纯文本或空返回。
