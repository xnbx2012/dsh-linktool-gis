# 地图制图数据分析规范

## 1. 目标

本文件用于指导地图制图前的数据事实采集工作。

数据分析阶段的任务不是决定最终符号、配色或布局，而是准确获取制图所需的基础事实，包括：

1. 输入数据在哪里；
2. 数据是否存在且可读取；
3. 数据是什么类型；
4. 数据的空间属性是什么；
5. 数据有哪些字段；
6. 属性表中有哪些样本值；
7. 哪些图层可能作为主图层或辅助图层；
8. 是否存在会阻碍制图的问题。

数据分析结果将传递给后续规范：

- `FieldType-Judgement.md`：判断字段类型；
- `SymbolSystem-design.md`：设计符号系统；
- `ColorScheme-design.md`：设计配色方案；
- `MapCheck.md`：检查最终图件质量。

---

## 2. 数据分析边界

本文件只负责“数据事实采集”和“制图可用性初筛”。

### 2.1 本文件负责

- 识别输入数据；
- 检查 GDB 内容；
- 检查数据属性；
- 抽样查看属性表；
- 记录字段信息；
- 记录空间范围和坐标系；
- 记录候选主图层和辅助图层；
- 发现数据问题。

### 2.2 本文件不负责

- 不负责最终字段类型判断；
- 不负责符号系统选择；
- 不负责配色方案设计；
- 不负责图层样式设计；
- 不负责图件美观性检查。

---

## 3. 必须使用的 ArcGIS MCP 工具

制图前制图数据分析必须使用以下 ArcGIS MCP 工具：

```text
list_gdb_contents
get_data_properties
query_feature_attributes
```

### 3.1 `list_gdb_contents`

当用户提供 `.gdb` 路径，但未明确具体图层时使用。

用于获取：

- GDB 中的要素类；
- GDB 中的栅格数据；
- GDB 中的表；
- Feature Dataset；
- 数据名称和路径；
- 初步字段数量或几何类型，如工具返回。

### 3.2 `get_data_properties`

对候选图层使用。

用于获取：

- 数据类型；
- 几何类型；
- 坐标系；
- 空间范围；
- 字段列表；
- 要素数量；
- 栅格分辨率和值域，如适用。

### 3.3 `query_feature_attributes`

对候选主图层使用。

用于抽样获取：

- 属性表样本；
- 字段实际取值；
- 字段空值情况；
- 字段值示例；
- 字段取值是否稳定；
- 可能的分类值或等级值。

建议限制返回数量：

```text
max_records = 50 或 100
```

## 4. 数据分析流程

### 4.1 识别输入数据

从用户需求中提取：

- GDB 路径；
- Feature Class 路径；
- Shapefile 路径；
- 栅格路径；
- 表路径；
- 用户指定图层；
- 用户指定字段；
- 用户指定研究区；
- 用户指定输出地图主题。

如果用户只提供 GDB，不提供具体图层，应先调用 `list_gdb_contents`。

### 4.2 建立候选图层清单

将可用图层初步归类为：

| 类型 | 说明 |
|---|---|
| 候选主图层 | 可能表达地图主题的图层 |
| 候选辅助图层 | 可能辅助定位或增强空间背景的图层 |
| 候选边界图层 | 行政边界、研究区边界等 |
| 候选标注图层 | 可能提供名称、编号或地名标注的图层 |

注意：此处只做候选归类，不做最终符号设计。

### 4.3 检查候选图层属性

对每个候选图层调用 `get_data_properties`，记录：

- 图层路径；
- 数据类型；
- 几何类型；
- 坐标系；
- 空间范围；
- 要素数量；
- 字段列表；
- 字段类型；
- 字段别名；
- 是否为空数据；
- 是否存在明显异常。

### 4.4 抽样查看主图层属性表

对候选主图层调用 `query_feature_attributes`，记录：

- 字段样本值；
- 字段取值示例；
- 字段空值情况；
- 字段唯一值初步情况；
- 用户指定字段是否存在；
- 是否存在明显可用于专题表达的业务字段。

注意：此阶段只记录事实，不直接替代字段类型判断。

## 5. 需要采集的数据事实

### 5.1 空间事实

| 项目 | 说明 |
|---|---|
| 数据路径 | 原始路径或工作区路径 |
| 数据类型 | FeatureClass、Shapefile、Raster、Table 等 |
| 几何类型 | Point、Polyline、Polygon 等 |
| 坐标系 | 名称、WKID、单位 |
| 空间范围 | xmin、ymin、xmax、ymax |
| 要素数量 | feature count |
| 是否为空 | 要素数量是否为 0 |
| 是否异常 | 范围、坐标系、路径是否异常 |

### 5.2 字段事实

| 项目 | 说明 |
|---|---|
| 字段名 | 原始字段名 |
| 字段别名 | 中文别名或业务名 |
| 字段类型 | String、Integer、Double 等 |
| 示例值 | 属性表样本值 |
| 空值情况 | 是否存在大量空值 |
| 唯一值线索 | 样本中是否出现多类取值 |
| 用户指定字段 | 用户指定字段是否存在 |

### 5.3 任务事实

| 项目 | 说明 |
|---|---|
| 地图主题 | 用户想表达什么 |
| 研究区 | 用户指定范围 |
| 输出要求 | 文件名、尺寸、正式图或草图 |
| 配色要求 | 用户是否提供色带 |
| 标注要求 | 是否指定标注字段 |

## 7. 异常和中止条件

如果出现以下情况，应停止或暂缓制图，并向用户说明原因：

1. 数据路径不存在；
2. 数据无法读取；
3. 主图层为空；
4. 用户指定字段不存在；
5. 坐标系缺失且影响制图；
6. 图层空间范围明显异常；
7. 属性表无法读取；
8. 没有任何可用于表达地图主题的字段。

如果问题不影响制图，但可能影响质量，应继续制图并在最终说明中标注风险。

## 8. 与后续规范的衔接

数据分析完成后，应按以下顺序进入后续规范：

```text
数据分析摘要
  ↓
FieldType-Judgement.md
  判断字段类型和标注字段
  ↓
SymbolSystem-design.md
  选择 renderer 和图层组织方式
  ↓
ColorScheme-design.md
  选择配色方案和色带
  ↓
MapCheck.md
  生成地图后进行图件检查
```

---

## 9. 核心原则

1. 数据分析阶段只采集事实，不替代后续设计决策。
2. 不得编造字段、属性值、坐标系或要素数量。
3. 所有判断应来自工具输出或用户明确说明。
4. 对不确定信息应明确标注“不确定”。
5. 数据问题应尽早暴露，避免后续制图失败。
6. 数据分析结果必须能被后续字段判断、符号设计、配色设计和图件检查直接使用。
