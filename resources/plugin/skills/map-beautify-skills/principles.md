# 美化原则
本文档定义在生成提示词时要遵循的具体规范

## 规则：
1. 原则上不允许私自增减地图的原始基本地理数据，要素，图幅
   - **明确**：此处的"要素"指空间实体（位置、形状、数量），视觉样式（配色、图例颜色）不在限制范围内
2. 生成的地图必须满足基本的制图规范
3. 原则上以用户提示词为最高标准
4. 如果收到无法列入任何类型skills的提示词，就原样输入给硅基流动
5. skills中给出的配色方案可以作为例子，但切忌将它们当作答案
6. 配色与图例颜色允许自由美化：在保持要素种类和空间分布不变的前提下，可调整点、线、面要素的配色及对应图例颜色，使之更美观、和谐、符合提示词要求


## 层级：
1. 当用户提出的要求自相矛盾的时候，遵循功能用途>地图主题>地图风格的原则


## 调用流程（给 Claude Code 或其他调度 LLM 参考，非硬约束）

任何模型调用 `beautify_image` 前，先阅读本文件与三份 skills 文件，然后按以下路径构造参数：

1. 识别用户的核心诉求，将其拆解为 4 个 MCP 参数：
   - `功能用途`：映射到科研图 / 直观图 / 宣传图 三者之一（同义词如"学术图""海报"按语义归并）
   - `地图主题`：先尝试映射到地图主题.md 的 8 大类或任一子类；若无法归并，直接原样传入（按规则 4 处理）
   - `地图风格`：先尝试映射到地图风格.md 的 6 大类或任一子类；与用户要求冲突或匹配度低时以用户原文为准（规则 3）
   - `图片内容描述`：告诉模型底图是什么（底图语义线索，不渲染为字符串）
   - `地图内容`：用户个性化描述（要求融入画面，不是作为字符串渲染）
2. MCP 收到参数后由 `main.py` 自动拼合为四段式 prompt：
   `【地图用途】… 【地图主题】…（含基本制图规范）… 【地图风格】…（用户优先）… 【地图内容】…（语义线索+个性化）`，末尾追加【红线】段
3. 调用者无需手动拼 prompt，只需传参；`main.py` 每次调用后将完整 prompt + 负面 prompt + API 参数落盘到 `{输出图}.prompt.txt`，并在 stdout 同步回显，便于溯源

未匹配任何 skills 分类的参数会按规则 4 原样传入硅基流动，skills 中的配色/数值仅作示例参考（规则 5）。
