## 0. 技能定位

本技能定义了"可疑数据"的判定标准——当数据文件名无法清晰表明其实际内容时，需要进一步检查属性表、字段列表或样例数据，以确定其业务含义。这是数据探索阶段的关键步骤，直接影响后续任务分解与工具链规划的准确性。

## 1. 可疑数据判定标准

满足以下**任意条件**的数据即判定为**可疑数据**，必须通过调用 `query_feature_attributes` 检查属性表来确认：

### 1.1 名称歧义（一词多义）

数据名称在 GIS 业务语境下有**多种可能的含义**，无法仅凭名称判断：

| 数据名称 | 歧义点 | 需确认事项 |
|---------|--------|-----------|
| `ZD.shp` | 宗地？等级？最大值？ | 检查字段列表确认实际含义 |
| `DL.shp` | 地类？道路？电力？ | 检查 DLBM/DLMC 字段确认 |
| `FW.shp` | 房屋？服务？范围？ | 检查几何类型和字段确认 |
| `NPP.tif` | 净初级生产力？其他缩写？ | 检查数值范围和单位确认 |
| `POI.shp` | 兴趣点？哪类 POI？ | 检查分类字段确认 |

**判定规则**：数据名称为**2-4个字母的缩写**，且在当前业务语境下存在 >=2 种合理解释。

### 1.2 名称过于通用

数据名称是**通用描述词**，缺乏具体业务指向：

| 数据名称 | 问题 | 需确认事项 |
|---------|------|-----------|
| `data.gdb` | 毫无业务信息 | 检查内部要素类列表 |
| `layer1.shp` | 默认命名，无业务含义 | 检查字段和几何类型 |
| `result.shp` | 不清楚由何种分析产生 | 检查字段和来源 |
| `temp.shp` | 临时文件，内容未知 | 检查字段确认可用性 |
| `output.gdb` | 哪个工具的输出？ | 检查内部要素类 |
| `Untitled.shp` | 默认命名 | 检查字段和几何类型 |

**判定规则**：数据名称为 **ArcGIS 默认名称**（layer1、output、result、temp、Untitled 等）或**无业务含义的通用术语**。

### 1.3 缺失时间维度

数据名称**未标注时间范围**，但任务涉及时间敏感型分析：

| 数据名称 | 缺失信息 | 需确认事项 |
|---------|---------|-----------|
| `LandUse.shp` | 哪一年的数据？ | 检查是否存在年份字段或属性中的时间信息 |
| `FarmlandQuality.gdb` | 哪一轮调查的数据？ | 检查字段中是否存在调查批次或年份 |
| `DEM.tif` | 哪个时期的测量？ | 检查元数据或数值范围特征 |
| `Population.shp` | 哪一年的统计？ | 检查统计年份字段 |

**判定规则**：任务涉及**时间序列分析、数据对比或时效性评估**，但数据名称缺少年份/批次/版本信息。

### 1.4 空间范围不明确

数据名称**未标注空间范围**，但任务涉及区域特定分析：

| 数据名称 | 问题 | 需确认事项 |
|---------|------|-----------|
| `dem.tif` | 覆盖哪个区域？ | 检查空间范围是否覆盖分析区域 |
| `Roads.shp` | 哪个区域的道路？ | 检查空间范围和属性中的行政区划 |
| `Farmland.shp` | 哪个县/市的耕地？ | 检查属性中的行政区划代码 |
| `Waterways.shp` | 哪个流域的水系？ | 检查空间范围和流域信息 |

**判定规则**：用户指定了**具体分析区域**，但数据名称未标注行政区划/流域/项目范围，且存在多个同名数据文件。

### 1.5 分类体系不明

数据包含**编码字段**，但编码规则未在数据名称或字段别名中说明：

| 数据名称 | 问题 | 需确认事项 |
|---------|------|-----------|
| `LandParcel.shp` | DLBM 编码含义是什么？ | 检查 DLBM 唯一值，与土地利用分类标准对比 |
| `FarmlandQuality.gdb` | 等级编码是 1-5 还是 1-10？ | 检查等级字段唯一值及分布 |
| `AdminBoundary.shp` | 行政区划代码是6位还是12位？ | 检查代码字段格式和长度 |
| `SoilData.gdb` | 土壤分类编码体系是什么？ | 检查分类字段唯一值和命名规则 |

**判定规则**：数据包含**数字编码字段**（如 DLBM=0101、DJBH=1），且编码规则无法从字段别名或数据名称推断。

### 1.6 字段含义模糊

字段名使用**缩写或非标准命名**，业务含义无法推断：

| 字段名称 | 问题 | 需确认事项 |
|---------|------|-----------|
| `ZD` | 缩写字段名 | 是"宗地"、"最大值"还是"优先级"？ |
| `AREA` | 单位不明 | 平方米、公顷还是平方千米？ |
| `TYPE` | 分类体系不明 | 检查唯一值确认分类含义 |
| `CODE` | 编码规则不明 | 检查数值范围和格式确认编码体系 |
| `FLAG` | 标志位含义不明 | 检查唯一值（0/1？Y/N？）确认含义 |
| `STATUS` | 状态码含义不明 | 检查唯一值确认状态含义 |

**判定规则**：字段名为**2-4个字母的缩写**，或字段别名缺失，且在当前业务语境下存在 >=2 种合理解释。

### 1.7 同名多源数据

工作空间中存在**名称相同或相似的多个数据文件**，无法确定使用哪一个：

| 场景 | 问题 | 需确认事项 |
|------|------|-----------|
| `01_DataBackup/Farmland.shp` 和 `01_DataBackup/Farmland2023.shp` | 哪个是最新的？ | 检查时间戳和属性差异 |
| `01_DataBackup/DLTB.shp` 和 `02_WorkSpace/DLTB_clip.shp` | 是否已处理过？ | 检查要素数量和范围差异 |
| 多个 GDB 中都包含 `LandParcel` 要素类 | 内容是否相同？ | 比较属性和空间范围 |

**判定规则**：存在 >=2 个名称相同或相似（仅后缀/版本号不同）的数据文件，且无法从路径或修改时间确定使用哪一个。

## 2. 可疑等级分类

根据不确定程度，划分为三个等级：

| 等级 | 含义 | 处理方式 |
|------|------|---------|
| 高度可疑 | 完全无法确定数据内容，可能用错数据 | **必须**检查属性表，**必须**与用户确认 |
| 中度可疑 | 可能存在歧义，需要核实 | **必须**检查属性表，可自行判断后记录 |
| 轻度可疑 | 基本可确定，但缺少辅助信息 | **建议**检查属性表，可跳过 |

**等级判定规则**：

- **高度可疑**：满足 1.1（名称歧义）或 1.2（通用名称）——**任一即可**
- **中度可疑**：满足 1.3（缺失时间）、1.4（范围不明）或 1.5（编码不明）——**任一即可**
- **轻度可疑**：满足 1.6（字段模糊）或 1.7（多源同名）——**任一即可**

## 3. 可疑数据记录格式

每个可疑数据条目按以下格式记录在 `02_WorkSpace/task_plan.md` 的 `## 可疑数据列表` 章节中：

```markdown
## 可疑数据列表

### 高度可疑（必须检查属性表 + 用户确认）

#### 1. `01_DataBackup/ZD.shp`
- **原因**：名称歧义 (1.1) — "ZD" 可能是"宗地"、"优先级"或"最大值"
- **可疑字段**：所有字段含义均未知
- **需确认事项**：
  - [ ] 检查字段列表确认数据业务含义
  - [ ] 检查样例数据（前10行）确认字段值范围
  - [ ] 与用户确认实际数据用途
- **状态**：待确认
- **结果**：（确认后填写）

#### 2. `01_DataBackup/data.gdb`
- **原因**：通用名称 (1.2) — ArcGIS 默认命名，无业务信息
- **可疑字段**：未知（需先检查内部要素类列表）
- **需确认事项**：
  - [ ] 调用 `list_gdb_contents` 检查内部要素类
  - [ ] 调用 `get_data_properties` 了解各要素类结构
  - [ ] 与用户确认哪些要素类与本任务相关
- **状态**：待确认
- **结果**：（确认后填写）
```

## 4. 可疑数据处理流程

```
数据探索阶段
    │
    ├─→ 浏览 01_DataBackup/ 目录结构
    │       │
    │       ├─→ 对照 1.1-1.7 标准检查每个数据文件
    │       │
    │       └─→ 标注可疑等级（高/中/低）
    │
    ├─→ 高度可疑数据处理：
    │       │
    │       ├─→ 调用 query_feature_attributes 检查属性表
    │       │
    │       ├─→ 调用 AskUserQuestion 与用户确认
    │       │
    │       └─→ 更新 task_plan.md 可疑数据列表
    │
    ├─→ 中度可疑数据处理：
    │       │
    │       ├─→ 调用 query_feature_attributes 检查属性表
    │       │
    │       ├─→ 自行判断并记录依据
    │       │
    │       └─→ 更新 task_plan.md 可疑数据列表
    │
    └─→ 轻度可疑数据处理：
            │
            ├─→ 调用 query_feature_attributes（建议执行）
            │
            └─→ 更新 task_plan.md 可疑数据列表
```

## 5. 与数据画像的集成

可疑数据确认结果应整合到 `@data-retrieval` 的数据画像报告中：

- **已确认数据**：在数据画像中标记为"已确认"，记录确认依据
- **未确认数据**：在数据画像中标记为"可疑"，描述原因和待确认事项
- **用户确认数据**：在数据画像中标记为"用户已确认"，记录用户提供的业务含义

## 6. 注意事项

1. **不要过度分类**：如果数据名称清晰（如"Roads.shp"、"Rivers.shp"）、字段别名完整、业务语境明显，则不要标记为可疑
2. **不要跳过可疑分类**：宁可多检查一次属性表，也不要做出错误假设导致后续分析出错
3. **记录判断依据**：每个可疑数据判定必须引用具体标准（1.1-1.7），而非凭直觉判断
4. **及时更新状态**：确认完成后立即在 `task_plan.md` 中更新处理状态和确认结果
5. **与用户沟通**：高度可疑数据必须与用户确认，不允许自行假设
