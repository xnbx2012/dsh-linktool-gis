**!IMPORTANT** 本 Skill 必须在 `@question-classify` 智能体中调用，严禁直接调用！

## 技能概述

本技能负责在 `@data-retrieval` 完成数据摸底后，基于数据画像报告对用户需求进行复杂性评估和分类，决定后续处理路径。

**核心原则**：数据摸底工作已完全由 `@data-retrieval` 完成，本技能**不**自行调用 MCP 工具进行数据探索。

## 完整工作流程

### 阶段一：接收数据画像

`@data-retrieval` 完成后，读取其生成的数据画像报告：

**报告路径**: `02_WorkSpace/data_profile.md`

从报告中提取关键信息作为分类依据：
- 数据源数量与类型
- 坐标系信息
- 几何类型
- 字段丰富度
- 数据量级
- 知识库参考（相关案例和处理模板）

### 阶段二：问题分类

#### 2.1 分类评估框架

基于数据画像报告，从五个维度评估：

| 评估维度 | 权重 | 说明 | 数据来源 |
|---------|------|------|---------|
| **工具数量** | 高 | 完成需求需要串联多少个 GIS 工具 | 用户需求 + 数据画像中的知识库参考 |
| **数据依赖** | 高 | 需要多少个数据源叠加分析 | 数据画像中的数据源概览 |
| **分析深度** | 高 | 是否涉及权重计算、综合评价、多因子叠加 | 用户需求 + 知识库参考 |
| **输出形式** | 中 | 需要生成图件/报告还是仅输出数据 | 用户需求 |
| **决策需求** | 中 | 是否需要提供选址/适宜性等决策支持 | 用户需求 + 数据画像中的业务关联 |

#### 2.2 三类问题判定标准

##### 决策支持类

满足以下**任一**条件：
- 需要串联 ≥3 个 GIS 工具
- 涉及多源数据叠加分析（3个及以上数据源）
- 需要权重计算、综合评价、多因子分析
- 需要生成分析报告
- 涉及适宜性评价、选址分析、决策支持等

**典型场景**：
- "分析一下哪里适合建垃圾站"
- "对这块地进行耕地质量评价"
- "做一下土地适宜性分析"
- "帮我做个综合分析并生成报告"

##### 简单分析类

满足以下**全部**条件：
- 需要 1-2 个 GIS 工具
- 仅涉及 1-2 个数据源
- 无权重计算、无综合评价
- 输出为数据文件（非报告）

**典型场景**：
- "对这个图层做个缓冲区分析"
- "把 A 图层裁剪到 B 范围"
- "合并这两个图层"
- "计算一下两个图层的相交区域"

##### 简单查询类

满足以下**任一**条件：
- 仅需查询数据属性或统计信息
- 无空间分析操作
- 结果可直接以文字形式返回
- 不需要生成任何数据文件

**典型场景**：
- "这个数据里有哪些字段"
- "查一下有多少个地块"
- "这个图层的坐标系是什么"
- "帮我看看数据的范围"

#### 2.3 分类决策流程

```
输入: 用户需求 + 数据画像报告

Step 1: 读取数据画像报告，提取关键特征
  - 数据源数量 → 判断数据复杂度
  - 字段丰富度 → 判断分析潜力
  - 知识库参考 → 判断任务类型

Step 2: 解析用户需求，提取关键操作词
  - 识别操作动词（分析、查询、统计、评价、选址...）
  - 识别输出要求（报告、图件、数据、直接输出...）

Step 3: 综合评估
  - 数据复杂度高 + 需求复杂 → 决策支持类
  - 数据复杂度低 + 需求简单 → 简单分析类
  - 无需数据处理 → 简单查询类

Step 4: 输出分类结果及依据
```

### 阶段三：路由执行

#### 3.1 决策支持类 → @task-plan

调用 `@task-plan` Agent，传递以下上下文：
- 用户原始需求
- 数据画像报告路径（`02_WorkSpace/data_profile.md`）
- 分类结论和建议

`@task-plan` 将跳过数据探索阶段，直接基于数据画像进入需求解读。

#### 3.2 简单分析类 → @gis-tool

调用 `@gis-tool` Agent，传递以下上下文：
- 明确的操作需求（已转换为 GIS 操作描述）
- 输入数据路径（从数据画像中获取）
- 预期输出路径
- 分类结论

#### 3.3 简单查询类 → 直接输出

使用 MCP 工具直接查询并输出结果：
- `list_gdb_contents`: 查看数据库结构
- `query_feature_attributes`: 查询要素属性
- `get_data_properties`: 获取数据属性信息

结果直接以文字形式返回给用户。

## 分类结果输出格式

```
问题分类结果

任务类型: [决策支持类 / 简单分析类 / 简单查询类]
分类依据:
  - 数据源数量: [N] 个
  - 数据复杂度: [高/中/低]
  - 需求特征: [简述]
  - 参考案例: [知识库中的相关案例]

处理路径: [→ @task-plan / → @gis-tool / → 直接查询输出]
```

## 注意事项

- **数据摸底由 @data-retrieval 完成**，本技能不自行调用 MCP 工具探索数据
- 分类必须**基于数据画像报告**的内容，不可凭空判断
- 分类必须明确为三类之一，不允许模糊归类
- 分类后必须立即执行路由，不可仅回复分类结果
- 工作空间三级目录规范（01_DataBackup 只读、02_WorkSpace 读写、03_Result 读写）
